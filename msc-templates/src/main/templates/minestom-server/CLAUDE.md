# {{name}}

Minestom server for Minecraft {{minestomMcVersion}}, Java {{javaVersion}}, Gradle Kotlin DSL. Scaffolded by Minecraft Server Creator.

## Commands

- `./gradlew build`: compile, run all tests and build the server jar. Run it after every change; it must pass before you stop.
- `./gradlew test --tests '*GreeterTest'`: one test class.
- `./gradlew run`: start the dev server in `run/` on {{serverIp}}:{{serverPort}}. Type `stop` to stop it.
- Server jar (runs on its own): `build/libs/{{projectId}}-{{version}}.jar`, start with `java -jar` from `run/`.

## Layout

- `src/main/java/{{packagePath}}/{{name}}Server.java`: entry point. Only wiring here (world, events, commands); put logic in its own classes.
- `Console.java`: reads `stop` and console commands from standard input, and runs the commands on the tick thread.
- `src/test/java/`: plain unit tests (`GreeterTest`) and Minestom test-environment tests (`{{name}}ServerTest`, `ConsoleTest`).
- `gradle/libs.versions.toml`: every dependency version. Add versions there, never inline in `build.gradle.kts`.
- `libs/msc-agent-minestom.jar`: Minecraft Server Creator's agent. Keep it; do not edit it.

## Minestom is not vanilla

- Minestom is a library. Nothing happens unless code here makes it happen: no vanilla commands (`/tp`, `/give`, `/time`...; the agent adds a dev-only `/tp` for the test player while msc-core runs the server), no mob AI, no block physics, no world saving, no redstone. Write what the server needs.
- The world is generated by the generator in `createWorld`; `main` keeps it in `run/world` with an `AnvilLoader` and saves it on `stop`, so builds survive `dev_cycle`. A crash loses changes since the last stop: call `world.saveChunksToStorage()` after big changes. Delete `run/world` to regenerate.
- Events: `MinecraftServer.getGlobalEventHandler().addListener(Event.class, e -> ...)`, or a child `EventNode` per feature.
- Commands: subclass `Command`, add syntaxes with `ArgumentType`, register with `MinecraftServer.getCommandManager().register(...)`. They run with the console as sender in tests and from `Console`.
- Blocks: `Block.STONE`, `Block.OAK_STAIRS.withProperty("facing", "north")`, `instance.setBlock(x, y, z, block)`. Chunks must be loaded first (`instance.loadChunk(cx, cz)`).
- Text is Adventure `Component`s (`Component.text("Hi", NamedTextColor.GREEN)`). Never use `§` codes.
- Threads: world and server state is touched only on the tick thread. Event listeners and player commands run there, and so do console commands: `Console` and msc's `server_command` hand each command to the scheduler, which runs it at the start of the next tick. Code on any other thread (a virtual thread, a `CompletableFuture` callback, an async event such as `AsyncPlayerConfigurationEvent`) hops back first with `MinecraftServer.getSchedulerManager().execute(() -> ...)`; then plain collections are safe.
- Do not block the tick thread (no files, network or sleeps in listeners or commands): do slow work on a virtual thread, then hop back with its result.

## Recipes

Built and tested against this project's pinned versions; copy them as they are.

A command with an argument, `src/main/java/{{packagePath}}/CountdownCommand.java`:

```java
package {{packageName}};

import net.kyori.adventure.text.Component;
import net.kyori.adventure.text.format.NamedTextColor;
import net.minestom.server.command.builder.Command;
import net.minestom.server.command.builder.arguments.ArgumentType;
import net.minestom.server.command.builder.arguments.number.ArgumentInteger;

/** {@code /countdown <seconds>}: a command with a number argument, 1 to 600. */
public final class CountdownCommand extends Command {
    public CountdownCommand() {
        super("countdown");
        ArgumentInteger seconds = ArgumentType.Integer("seconds");
        seconds.between(1, 600);
        setDefaultExecutor((sender, context) -> sender.sendMessage(Component.text("Usage: /countdown <seconds>")));
        addSyntax((sender, context) -> sender.sendMessage(
                Component.text("Starting in " + context.get(seconds) + "s", NamedTextColor.YELLOW)), seconds);
    }
}
```

A block-break listener on its own event node, `src/main/java/{{packagePath}}/BlockGuard.java`:

```java
package {{packageName}};

import net.minestom.server.event.EventFilter;
import net.minestom.server.event.EventNode;
import net.minestom.server.event.player.PlayerBlockBreakEvent;
import net.minestom.server.event.trait.InstanceEvent;
import net.minestom.server.instance.Instance;

/** Stops players breaking blocks in one instance. Add it with {@code events.addChild(BlockGuard.node(world))}. */
public final class BlockGuard {
    private BlockGuard() {
    }

    public static EventNode<InstanceEvent> node(Instance world) {
        EventNode<InstanceEvent> node = EventNode.value("block-guard", EventFilter.INSTANCE, world::equals);
        node.addListener(PlayerBlockBreakEvent.class, event -> event.setCancelled(true));
        return node;
    }
}
```

Their test, `src/test/java/{{packagePath}}/CountdownCommandTest.java`:

```java
package {{packageName}};

import static org.assertj.core.api.Assertions.assertThat;

import net.minestom.server.command.builder.CommandResult;
import net.minestom.server.coordinate.BlockVec;
import net.minestom.server.event.player.PlayerBlockBreakEvent;
import net.minestom.server.instance.Instance;
import net.minestom.server.instance.block.Block;
import net.minestom.server.instance.block.BlockFace;
import net.minestom.testing.Env;
import net.minestom.testing.EnvTest;
import org.junit.jupiter.api.Test;

@EnvTest
class CountdownCommandTest {
    @Test
    void countdownTakesSeconds(Env env) {
        env.process().command().register(new CountdownCommand());

        assertThat(env.process().command().executeServerCommand("countdown 5").getType())
                .isEqualTo(CommandResult.Type.SUCCESS);
    }

    @Test
    void blockGuardCancelsBreaks(Env env) {
        Instance world = {{name}}Server.createWorld(env.process().instance());
        env.process().eventHandler().addChild(BlockGuard.node(world));
        var player = env.createPlayer(world, {{name}}Server.SPAWN);
        var event = new PlayerBlockBreakEvent(player, world, Block.GRASS_BLOCK, Block.AIR, new BlockVec(0, -61, 0),
                BlockFace.TOP);

        env.process().eventHandler().call(event);

        assertThat(event.isCancelled()).isTrue();
    }
}
```

## Standard library (msc-stdlib)

The project depends on MSC's standard library (`libs.msc.stdlib.minestom`, shipped in `libs/repo/` with its sources, packed into the server jar). Use it before writing your own. `Stdlib.init(MinecraftServer.process())` runs in `main` (the template does it); in tests call `Stdlib.init(env.process())` first.

Find what you need without reading sources: `grep -n "Gui" libs/stdlib/API.md` (one line per public method, with what it does), `graphify query "menu with a confirm button" --graph libs/stdlib/graphify-out/graph.json`, then read only the lines you need in `libs/stdlib/src/`. Packages are under `io.github.imnotstable.msc.stdlib`.

- Menus: `Gui.chest(rows, title)` with `set(slot, item, click -> ...)`, `fill`, `border`, `editable`, `onClose`, `open(player)`; `Gui.paged(rows, title, list, icon, (entry, click) -> ...)`. Items cannot be taken out except from `editable` slots.
- Items: `ItemBuilder.of(Material)` with `name`, `lore`, `glow`, `hideTooltip`, `model`, `tag(tag, value)`, `raw()` for other data components; `ItemBuilder.read(item, tag)`, `ItemBuilder.filler()`.
- Text: `Text.mm("<green>Hi <name>", "name", value)` (values go in as plain text, `Component`s as they are), `Text.plain`.
- Particles: `ParticleEffect.of(Particle.FLAME)` or `ParticleEffect.dust(color, size)`, then `spawn(instance, point)`, `draw(instance, origin, points)` or `play(scheduler, instance, origin, period, frames, frame -> points)`. Shapes in `Shapes` (`circle`, `sphere`, `helix`, `star`, `cuboidEdges`, ...); `Locations.facing` turns them to where a player looks. Scoreboards: Minestom's own `Sidebar`.
- Databases: `Database.open(DatabaseConfig.sqlite(Path.of("data.db")))` (the SQLite driver is a dependency; add the MySQL, MariaDB or PostgreSQL driver to `libs.versions.toml` for `DatabaseConfig.server(...)`). `update`, `insert`, `query`, `queryOne`, `transaction`, `async(db -> ...)`; `Table.named(...)` schemas, `db.migrate(...)` with `Migration.of(...)`, `Store.sql(db, table, Codec.json(Account.class))` records by key, `Store.memory()` in tests.
- Player data: `PlayerData.create(store, defaults)` loads each player's record while they configure, saves it when they leave; `get`, `update`, `saveAll` (call before stopping).
- Shared with every platform (see `libs/stdlib/API.md`): `Repository` records with no SQL, `Store` (`jsonFiles`, `cached`, `writeBehind`), `Cache`, `Economy`, `Config`, `Messenger`, `Redis`/`Mongo` (add their driver first), `Format`, `RateLimiter`, `Leaderboard`, `EventBus`, `Sequence`, `Cuboid`/`Region`, `Randoms`.
- Time: `Cooldowns` (`tryUse`, `remaining`), `Durations.parse("1h30m")`, `Durations.format`, `Stdlib.scheduler()` (`later`, `repeat`, `countdown`). Loot: `WeightedRandom`.

## Tests

- Every change comes with a test. Pure logic: plain JUnit + AssertJ. Worlds, players, events, commands: Minestom's test environment.
- Pattern: annotate the class with `@EnvTest` and take `Env env` as a test parameter. `env.createFlatInstance()` or your own `createWorld(env.process().instance())`; `env.createPlayer(instance, pos)` connects a player; `env.process().command().executeServerCommand("hello")` runs a command; `env.tick()` advances one tick.
- Compare messages as plain text (`PlainTextComponentSerializer`), not by component equality.

## Minecraft Server Creator

- `MscAgent.start()` in `main` lets the AI's world tools (read, build, render, undo) work on the instance named `"world"` (`MscAgent.name(instance, "world")`). Name other instances to make them visible by name.
- `server_command` runs commands this server registered; there are no vanilla commands unless you add them.
- No Mojang server jar and no EULA step: Minestom implements the protocol itself. Players still need a Minecraft {{minestomMcVersion}} client.
