# ADR 0009: Fabric agent and Fabric template

Status: accepted, 2026-11-11. Decided by Claude under Jeremiah's hand-over of build decisions.

## Context

`msc-agent-fabric` is the Fabric counterpart of the Paper agent ([ADR 0006](0006-paper-agent.md)): a server-side mod that carries out the core's operations (`Ops` in msc-protocol), so the core's tools work against a Fabric server. `msc-templates` also needs a Fabric starter project. Minecraft 26.x ships unobfuscated, so Fabric uses Mojang's names directly and there are no Yarn mappings for 26.3.

## Decisions

1. **Same Minecraft release as Paper: 26.3.** Fabric supports it: Fabric Loader 0.20.1, Fabric API 0.166.0+26.3, Fabric Loom 1.19.4 (the non-remapping `net.fabricmc.fabric-loom` plugin, since there is nothing to remap). All four versions live in the version catalog.
2. **Protocol behaviour is identical to the Paper agent.** Same operation catalogue, error codes, limits, 20 ms tick budget, 2 minute timeout, skipping blocks already in the target state, physics off for `world.fill`, in-memory undo of about 8 full-size edits where undo returns a new id, `minecraft:void_air` outside the build height, the same connection settings, backoff and reconnect, and the same events. The classes that are already platform-neutral (`SlicedJob`, `MainThread`, `EditHistory`, `PackedPos`, `CoreAddress`, `AgentRoutes`) are copied from the Paper agent, not shared: a shared `msc-agent-common` module would mean changing the Paper agent too. Extract one when a third agent (Minestom) needs the same classes.
3. **World names follow Paper.** The overworld is the server's `level-name` (usually `world`), the vanilla nether and end are `<level-name>_nether` and `<level-name>_the_end`, and other dimensions use their id (`mymod:mining`). A dimension id is accepted too (`minecraft:the_nether`). The core and the AI see the same names on both platforms, and the overworld comes first in `server.info`, which the core uses as the default world.
4. **Minecraft access sits behind two small interfaces**, `AgentLevel` (blocks, heights, entities of one world) and `ServerAccess` (versions, TPS, commands, packs). The operations, jobs and undo run against them, so they are unit tested with an in-memory world and real Minecraft block states (registries bootstrapped in the test JVM through `fabric-loader-junit`). There is no MockBukkit for Fabric; the Fabric implementations (`FabricLevel`, `FabricServerAccess`) are thin and need a real server to test.
5. **Main-thread work is driven by the server tick.** `TickMainThread` queues jobs and steps them from `ServerTickEvents.END_SERVER_TICK`. Concurrent jobs share one 20 ms budget, but every job gets at least one step per tick, so a quick call (`server.info`) never waits behind a large edit. When the server stops, queued jobs fail with `shutdown`.
6. **Block flags.** Without physics: `UPDATE_CLIENTS | UPDATE_KNOWN_SHAPE | UPDATE_SKIP_ON_PLACE | UPDATE_SKIP_BLOCK_ENTITY_SIDEEFFECTS`, so the block lands exactly as written. With physics: `UPDATE_ALL | UPDATE_SKIP_BLOCK_ENTITY_SIDEEFFECTS`. Replacing a container never spills its items, as with Paper.
7. **`onlyReplace` matches like Paper's `BlockData#matches`.** A filter compares the block and only the properties written in it, so `minecraft:oak_stairs` matches every stair state.
8. **Commands run as the server console** (`createCommandSourceStack()` with a source that captures every message). Success comes from Brigadier's result callback, so it means the command was found and reported success, as on Paper.
9. **Resource packs** clear the player's packs and push the new one (Paper's `replace(true)`), and are re-sent to players who join later.
10. **One self-contained, server-only mod jar.** `"environment": "server"` with a `DedicatedServerModInitializer`; Minecraft is compiled against the dedicated server jar only (`serverOnlyMinecraftJar()`). msc-protocol and the three Fabric API modules the agent uses (`fabric-api-base`, `fabric-lifecycle-events-v1`, `fabric-networking-api-v1`) are nested in the jar (jar-in-jar), so a server needs only Fabric Loader and this jar. If the server also has full Fabric API, Loader picks the newest copy of each module. Gson comes from Minecraft.
11. **Build wiring.** Loom adds its own repositories, which the repo's `RepositoriesMode.FAIL_ON_PROJECT_REPOS` forbids at project level, so `settings.gradle.kts` applies Loom's settings plugin `net.fabricmc.fabric-loom-repositories` (which declares them in the settings) and adds `maven.fabricmc.net`. Loom 1.19 requires Gradle itself to run on Java 25, so `gradle/gradle-daemon-jvm.properties` asks for a Java 25 daemon; Gradle finds a local JDK 25 whatever `JAVA_HOME` says. The plugin version in settings must match `fabric-loom` in the catalog (settings plugins can't read the catalog).
12. **Template `fabric-mod`.** Mirrors `paper-plugin`: Java 25, Gradle KTS with Loom, own wrapper and version catalog, a `/hello` Brigadier command and a join greeting through Fabric API events, a plain JUnit test and a command test that runs the real command tree, `CLAUDE.md` conventions (Mojang names, server-only, events before mixins), and a dev server in `run/` (`./gradlew runServer`). The dev server config is `paper-server`'s, which is plain vanilla config, so there is no separate `fabric-server` template. The template also carries `gradle/gradle-daemon-jvm.properties` for Loom. The default project description no longer says "a Paper plugin".

## Consequences

- The core's lifecycle tools are still Paper-only: it downloads Paper and puts the agent in `plugins/`. Starting a Fabric server needs a core change: download the Fabric server launcher (`meta.fabricmc.net/v2/versions/loader/26.3/<loader>/<installer>/server/jar`) and copy `msc-agent-fabric.jar` into `mods/`. World and server tools work as soon as the agent connects.
- Verified in the cloud container: 33 agent tests pass, the template scaffolds, builds and passes its tests, and the mod resolves and loads on a real Fabric 26.3 server (it stopped at the EULA, which was not accepted). Not yet verified on a running world: the Fabric implementations of block access, commands and packs.
- Everyone building the repo needs a JDK 25 available to Gradle, which the build already required for compiling.
